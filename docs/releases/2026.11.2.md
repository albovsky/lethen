# lethen 2026.11.2

Lethen 2026.11.2 reads Xcode projects stored in Xcode 27.2's JSON project format and fixes a set of false positives in macro-generated code and skipped `#if` branches. It requires Swift 6.3 (Xcode 26.4) or later, like 2026.11.1, and has no breaking changes.

## Highlights

- **Xcode 27.2's JSON project format.** A `.xcodeproj` that stores its project in `project.xcproj` instead of `project.pbxproj` is now scanned, instead of stopping with an error. Lethen reads from it everything it reads from `project.pbxproj`: targets, file memberships, synchronized folders and their exceptions, build phases, Run Script paths, local packages and per-configuration build settings. A project converted by Xcode 27.2 scans as its original did, and reading the format needs no new dependency (#189).
- **Macro peers.** An unused protocol annotated with a peer macro is reported when its only reference comes from the unused class that the macro generated (#192).
- **Skipped `#if` branches.** In a branch the build skipped:
  - a construction through an SDK alias such as `CFloat`, or through a class or type alias the build references, now reaches the extension initializers it can call (#162, #163);
  - a bare name inside a type's body counts for that type's members, as `self.name` already did (#200).
- **Developer tasks.** They run directly from `dev/`, with pinned SwiftFormat and SwiftLint installed by `dev/install-lint-tools`.

## Measured results

The [precision scorecard](https://github.com/albovsky/lethen/blob/2026.11.2/docs/validation/precision-corpus.md) now samples 366 findings across five pinned projects, including a held-out Vapor service, SwiftPackageIndex-Server.

| Release criterion | Target | Result | Met |
| --- | --- | --- | --- |
| Sampled precision on the corpus | 95 % | 89.5 % pooled over 366 sampled findings; 94.4 % weighted by each project's findings | **no** |
| Precision of sampled `certain` findings | not a release criterion | 94.6 % (318 of 336 with a verdict; 91.7–96.6 %) | n/a |
| Precision of sampled `likely` findings | not a release criterion | 25.9 % (7 of 27; 13.2–44.7 %) | n/a |

The larger sample lowers the `certain` figure from 2026.11.1's 100 % over 82 findings. Most of the new `certain` false positives come from the held-out server, at 74.2 %, which the scorecard breaks down.

## Verification and limits

The release commit must pass the `Required checks` gate: the Swift 6.4 / Xcode 27 baseline, the macOS 6.3 / Xcode 26.4 job, Linux 6.3 and 6.4, Bazel on macOS and Linux, and the Linux release tarballs smoke-tested on Ubuntu 22.04, 24.04 and 26.04 images. In the primary job, the JSON project format tests convert Lethen's Xcode fixtures with Xcode 27.2. They check that each converted fixture loads as its property list form and that it scans the same. Intel source builds are not tested in CI.

When Xcode 27.2 converts a project, it drops any folder membership exception that names a subfolder rather than a file, in either direction. Lethen reads what the JSON file holds. Parts of the format that Lethen does not use are not read, such as header roles, compiler flags, platform filters and build rules. A project that declares `required-capabilities` stops with an error.

## Platforms and installation

**Platforms:** macOS release binaries and Homebrew are Apple silicon only (macOS 15 or later). Intel Macs build from source with a supported Xcode 26.x; see the [platform policy](https://github.com/albovsky/lethen/blob/master/CONTRIBUTING.md#supported-platforms). Linux x86_64 and aarch64 can use the release tarballs, which need glibc 2.35 or later and a Swift 6.3 or newer toolchain, or build from source.

Install with `brew install albovsky/tap/lethen`, or download the [arm64 zip](https://github.com/albovsky/lethen/releases/download/2026.11.2/lethen-2026.11.2-macos-arm64.zip) and [checksums](https://github.com/albovsky/lethen/releases/download/2026.11.2/SHA256SUMS). Xcode or the Command Line Tools must be installed. On Linux, download `lethen-2026.11.2-linux-x86_64.tar.gz` or `lethen-2026.11.2-linux-aarch64.tar.gz`. The [installation guide](https://github.com/albovsky/lethen/blob/master/docs/guide.md#installation) includes checksum verification; the [README](https://github.com/albovsky/lethen/blob/2026.11.2/README.md#linux) shows how to install a Linux tarball.

### Source installation

Select a full Xcode installation on macOS, for example `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, then:

```sh
git clone --branch 2026.11.2 --depth 1 https://github.com/albovsky/lethen.git
cd lethen
swift build -c release --product lethen
lethen_bin_dir="$(swift build -c release --show-bin-path)"
"$lethen_bin_dir/lethen" version
mkdir -p "$HOME/.local/bin"
install -m 755 "$lethen_bin_dir/lethen" "$HOME/.local/bin/lethen"
export PATH="$HOME/.local/bin:$PATH"
lethen scan --project-root /path/to/your/project --disable-update-check
```

Keep the PATH export in your shell profile. Stable builds are offered stable releases by the optional update checker.
