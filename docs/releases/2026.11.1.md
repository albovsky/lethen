# lethen 2026.11.1

Lethen 2026.11.1 changes what the GitHub Action fails on, makes the `xcode` format show where trustworthy results end, and grades the precision scorecard per confidence tier. It also fixes a compilation-cache bug that silently dropped findings and a set of false positives. It requires Swift 6.3 (Xcode 26.4) or later, like 2026.10.1.

## Breaking changes

- The GitHub Action now fails a strict scan only on `certain` results when `min-confidence` is not set. In the `github-actions` format `likely` results are still annotated as notices and the step's log says how many there were, but they no longer fail the step or count in the `count` output. Other formats run the scan with `--min-confidence certain`. Set `min-confidence: likely` to keep the old behavior. `likely` notices from a `working-directory` below the repository root now point at the right file.

## Highlights

- **Action default.** A strict scan in the Action fails only on `certain` results unless `min-confidence` is set. The corpus found no false positive among 82 sampled `certain` results and 1 true positive among 8 sampled `likely` ones.
- **Readable `xcode` output.** `likely` results come after a `Likely unused, check by hand:` line, and redundant public accessibility and superfluous ignore comments come last under their own header. A line before the summary says what was scanned. The headers go to standard error, so standard output stays parseable, and `--quiet` leaves them out.
- **Scorecard per tier.** The precision scorecard gives `certain` and `likely` their own precision with a 95 % Wilson interval, per project and overall, and shows the overall figure weighted by each project's findings.
- **Finding-drop gate and recall canaries.** The nightly corpus fails when a project loses more than 2 % of its findings since the merge base or the newest release tag, unless `docs/validation/precision-corpus.md` holds an adjudication line for the drop. A recall test keeps a set of dead declarations that must stay reported, each next to a live twin that must stay used (#227).
- **Compilation-cache fix.** An Xcode compilation-cache hit could leave compiled files without index units and lose findings without saying so. Managed builds now turn the cache off, and a `--skip-build` scan of an incomplete store stops with an error.
- **`--derived-data-path`.** With `--skip-build`, it reads the index of an Xcode project that a pipeline built into its own `-derivedDataPath`, and stops with a stale-index error when a source file was edited after the build.
- **Fewer false positives.** Fixed classes include unused properties of `@Observable` classes that were reported inconsistently, `private(set)` taken as `private`, `Encodable` existentials, generic results returned through `if` and `switch`, and `#if` branches the build skipped.

## Measured results

All figures come from `corpus/precision.py --check` at the release commit, which prints the same numbers as `docs/validation/precision-corpus.md`. The Wikipedia iOS `likely` share and the scan-performance figures were not re-measured for this release, so the table has only the precision rows.

| Release criterion | Target | Result | Met |
| --- | --- | --- | --- |
| Sampled precision on the corpus | 95 % | 92.2 % (83 TP, 7 FP of 90 sampled findings; 3,412 findings in the corpus); 96.0 % weighted by each project's findings | **no** |
| Precision of sampled `certain` findings | not a release criterion | 100.0 % (82 of 82; 95.5–100.0 %) | n/a |
| Precision of sampled `likely` findings | not a release criterion | 12.5 % (1 of 8; 2.2–47.1 %) | n/a |

The 95 % target is still not met on the pooled figure. The `certain` tier is at 100 % with the interval above. Sample sizes are small.

## Fixes

The full list is in `CHANGELOG.md`. Among them: an Xcode compilation-cache hit no longer leaves compiled files without index units (#196); `private(set)` and `fileprivate(set)` no longer give a declaration their access level (#199); the ids of unused-import findings no longer depend on how `--project-root` is spelled (#184); an Xcode project in the JSON project format stops with a clear error instead of an XcodeProj error (#189).

## Verification and limits

The release commit must pass the `Required checks` gate: the Swift 6.4 / Xcode 27 baseline, the macOS 6.3 / Xcode 26.4 job, Linux 6.3 and 6.4, Bazel on macOS and Linux, and the Linux release tarballs smoke-tested on Ubuntu 22.04, 24.04 and 26.04 images. The [verified combinations](https://github.com/albovsky/lethen/blob/2026.11.1/README.md#verified-combinations) table has no 2026.11.1 row yet, so nothing in it is evidence for this release. The [precision scorecard](https://github.com/albovsky/lethen/blob/2026.11.1/docs/validation/precision-corpus.md) records how precision is sampled. Intel source builds are not tested in CI.

The new index completeness check does not detect a target that has no unit of its own module at all, because Lethen cannot tell it from a target the schemes do not build. A file the build leaves out on purpose, such as one behind a platform filter, is reported as missing; exclude it with `--index-exclude`. An explicit `--index-store-path` is not checked.

## Platforms and installation

**Platforms:** macOS release binaries and Homebrew are Apple silicon only (macOS 15 or later). Intel Macs build from source with a supported Xcode 26.x; see the [platform policy](https://github.com/albovsky/lethen/blob/master/CONTRIBUTING.md#supported-platforms). Linux x86_64 and aarch64 can use the release tarballs, which need glibc 2.35 or later and a Swift 6.3 or newer toolchain, or build from source.

Install with `brew install albovsky/tap/lethen`, or download the [arm64 zip](https://github.com/albovsky/lethen/releases/download/2026.11.1/lethen-2026.11.1-macos-arm64.zip) and [checksums](https://github.com/albovsky/lethen/releases/download/2026.11.1/SHA256SUMS). Xcode or the Command Line Tools must be installed. On Linux, download `lethen-2026.11.1-linux-x86_64.tar.gz` or `lethen-2026.11.1-linux-aarch64.tar.gz`. The [installation guide](https://github.com/albovsky/lethen/blob/master/docs/guide.md#installation) includes checksum verification; the [README](https://github.com/albovsky/lethen/blob/2026.11.1/README.md#linux) shows how to install a Linux tarball.

### Source installation

Select a full Xcode installation on macOS, for example `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, then:

```sh
git clone --branch 2026.11.1 --depth 1 https://github.com/albovsky/lethen.git
cd lethen
swift build -c release --product lethen
lethen_bin_dir="$(swift build -c release --show-bin-path)"
"$lethen_bin_dir/lethen" version
mkdir -p "$HOME/.local/bin"
install -m 755 "$lethen_bin_dir/lethen" "$HOME/.local/bin/lethen"
export PATH="$HOME/.local/bin:$PATH"
lethen scan --project-root /path/to/your/project --disable-update-check
```

Keep the PATH export in your shell profile. Stable builds are offered stable releases by the optional update checker.
